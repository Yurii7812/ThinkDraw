# 紙PKM(スキャンした紙のノート)

紙の Folgezettel ノートをスキャンして取り込み、左上の手書き ID で自動的に並べて見る機能。紙の中身は書き直さず、画像のまま持つ。

## 使い方

1. 紙をまとめてスキャンする(PDF でも画像でもよい。順番はばらばらでよい)。
2. 右上の紙のアイコン(または Ctrl+P)で「紙PKM」を開く。
3. PDF・画像をこの画面に落とす(または上の「取り込む」ボタンで選ぶ)。
4. ページに分けて、左上の ID を OCR で読む(ローカルの画像モデル。CPU だけだと 1 ページ 30 秒ほど。画面を閉じてほかの作業をしていてよい。読み終わると知らせる)。
5. 確かめが要るページだけが出る。ID を直す(候補を押すか、打つ)→「取り込む」。
   自動で決まったページは「見る」で開けば直せる。
6. 左の 0・1・2… から系列を選び、ID を選ぶとスキャン画像が出る。← → でページ送り、+ − 0 で拡大縮小、F で全画面。
7. 「キャンバスに置く」で、いま開いているグループに紙のページを置ける。デジタルのノードと線でつなげる。ダブルクリックで紙PKM のそのページが開く。

後日スキャンした分も、同じ手順で落とすだけでよい。既存のページは変えずに、正しい位置に入る。

### ID の書き方(読める形)

| 種類 | 例 | 系列 |
|---|---|---|
| 通常ノート | `1` `1a` `1a1` `1a1a` `2c` `3a1` | 先頭の数字 |
| 索引・まとめ | `1a-1` `1a-1a` `1a3-1` `1a1-1` | 先頭の数字 |
| 全体索引 | `0`(入口) `0-1` `0-1a` `0-2` | 0 |

- 数字と英字が交互に並ぶ。ハイフンの後ろも数字から始まる。
- 古い紙(`1` `2` から始めていた頃)も同じ規則で読める。
- `3 - 紙のPKMについて` のように「ID - 題」と書いたページは、ハイフンの後ろが数字でないので `3` として読む。

### 並び順

索引・まとめは、その対象の直前。対象の子は対象の後ろ。

```
0-1, 0-1a, 0-2
1a-1, 1a-1a, 1a-1b, 1a-2, 1a, 1a1-1, 1a1, 1a1a, 1a2, 1a10, 1b
```

数字は数として比べる(`1a2` < `1a10`)。英字は短い方が先、同じ長さなら文字の順(`1z` < `1aa`)。
同じ ID のページが複数あれば、取り込んだ順。

## OCR のしくみと、自動で確定する条件

- ローカルの ollama の画像モデル 2 つで読む(既定: `qwen2.5vl:7b` と `gemma3:4b`。無料・キー不要・ネットに出さない)。
- 左上(ページの幅 30%・高さ 9%)を切り出し、薄いインクを濃くする。
- CPU だけだと、画像を読み込む部分が 1 回 1 分前後かかる。そこで何ページか分の切り出しを 1 枚に縦に並べ(右に R1・R2… の印)、まとめて読む(qwen は 8 枚、gemma は 4 枚ずつ)。

次の条件をすべて満たすときだけ自動で確定する。

- 2 つのモデルの読みが同じ正しい形の ID
- その ID のページがまだ無く、今回の取り込みの中でも重ならない
- 前の番号(`1d` なら `1a`・`1b`・`1c`)が、一覧か今回の取り込みにある(番号の抜けは読み違いのことが多い。例: `1b` を両方のモデルが `1d` と読んだ)

それ以外(読みが分かれた・形が正しくない・同じ ID がすでにある・同じ画像を取り込み済み・モデルが 1 つしか使えない)はすべて要確認。
`3bl` → `3b1` のような、よくある読み違いを直した形は「候補」として出すだけで、勝手には採らない。

OCR を使えない(ollama が動いていない・モデルが無い)ときは、読めたふりをせず、全ページを要確認にして理由を出す。

### 実物で測った結果(2026-11-23、利用者のスキャン 29 枚、古い番号の付け方、CPU だけ・i7-1280P)

| | 結果 |
|---|---|
| 時間 | 951 秒(1 ページ約 33 秒) |
| 自動で確定 | 12 枚(誤り 0) |
| 要確認 | 17 枚。1 位の候補が正解のもの 14 枚 |
| 1 位の候補が正解(全体) | 26/29 |

手で直す必要があったのは 3 枚: `1`(後ろの消した字ごと `1a` と読んだ)・`1b`(両方のモデルが `1d`。番号の抜けの確認で要確認になる)・`3a2`(`3r2`)。
要確認のうち 4 枚は、同じ ID が本当に 2 枚ずつある古い紙(`3`・`3a`)。
29 枚だけの結果なので、ほかの紙・書き方での精度は分からない。

準備: `ollama pull qwen2.5vl:7b` と `ollama pull gemma3:4b`(合わせて約 9GB)。

## 保存(vault の中)

```
paper/
  index.json          ページの一覧(内部ID・ID・状態・OCR の読み・元のファイル)
  pages/<内部ID>.jpg  ページの画像
  thumbs/ crops/      一覧用の小さな絵・左上の切り出し
  sources/            取り込んだ元の PDF・画像(sha256 の名前。消さない)
  backups/            index.json を書き換える前の写し(新しい 30 件)
  .staging/           取り込みの途中(確定するまで一覧に入らない)
  .trash/             一覧から外したページ(画像も残る)
```

- 内部ID(`p` + 12 桁)はページごとに自動で付ける。紙の ID とは別。ID を直しても内部ID は変わらないので、キャンバスに置いたノード(frontmatter の `paper:`)は切れない。
- デジタルのノードの ID(10 文字)とは形も場所も別なので、紙の `1a1` とデジタルの物が衝突しない。
- 取り込みは「画像を置く → 最後に一覧を書く」の順。途中で失敗しても一覧は前のまま。
- 書き出し: 上の「書き出す」で、系列ごとのフォルダに `並び順_ID_内部ID.jpg` で写し、`index.json` も置く。

## 詳細設定

上の歯車。OCR のモデル(`名前×まとめる枚数` をカンマで区切る)・ollama の場所・左上の切り出しの大きさ(ページに対する %)。
設定はアプリの設定(`config.json`)に入る。

## OCR の精度を測る

```
npx esbuild tools/paper-ocr-eval.ts --bundle --platform=node --format=esm --outfile=/tmp/eval.mjs
node /tmp/eval.mjs <作業用フォルダ> <正解.tsv(ファイル名<TAB>ID)> <画像…>
OCR_MODELS="qwen2.5vl:7b×8,gemma3:4b×4" node /tmp/eval.mjs …
```

## まだ無いもの(将来)

- 本文の中の手書きリンク(`文 → ID`、赤い ID)の認識と、そこからのジャンプ
- `(n)` の位置へのジャンプ、スキャンした索引からのジャンプ、自動バックリンク
- ページの回転・傾きの自動補正(横向き・逆さのスキャン)。左上を広めに切り出すことで、少しのずれには対応する
- ノートの本文から紙のページへのリンク(いまはキャンバスに置いて線でつなぐ)
